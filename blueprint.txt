# iSAST — Full Application Build Specification

## 1. Product definition

**iSAST** is a zero-configuration, CLI-first SAST orchestrator combining:

* **OpenGrep** — broad, multi-language SAST and taint analysis
* **CodeQL** — deeper semantic/data-flow analysis
* **AI analysis** — finding validation, normalization, deduplication, severity refinement, and professional wording
* **CSV/JSON reporting** — designed for downstream ingestion into ThreatVault/CodXprt

The primary UX must remain:

```bash
python isast.py --source=/path/to/source --report=final.csv
```

No manual language selection.
No manual OpenGrep configuration.
No manual CodeQL commands.

# 3. Core design principles

### iSAST owns

```text
Detection
Dependency installation
Scanner execution
Build detection
Build isolation
SARIF parsing
Finding normalization
Fingerprinting
AI orchestration
Reporting
```

### AI owns

```text
Validation
False-positive assessment
Finding deduplication
Canonical naming
Description improvement
Severity recommendation
CWE/OWASP enrichment
Remediation wording
```

### iSAST must NOT

* claim exploitation without evidence
* delete raw scanner findings
* silently execute untrusted builds on the host
* require a specific AI vendor
* require users to configure languages
* require users to understand CodeQL

# 13. OpenGrep execution

OpenGrep runs across the source tree.

Recommended default:

```bash
opengrep scan \
    --config auto \
    --severity INFO \
    --sarif \
    --output opengrep.sarif \
    --exclude .git \
    --exclude node_modules \
    --exclude vendor \
    --exclude dist \
    --exclude build \
    --exclude target \
    --exclude coverage \
    --exclude .venv \
    --exclude venv \
    --exclude __pycache__ \
    .
```

The scanner should favor **recall over aggressive suppression**.

# 16. Build sandbox

The sandbox exists **only to execute project-controlled build activity**.

It is not required for OpenGrep.

It is not inherently required for CodeQL analysis.

```text
CodeQL
  │
  ▼
Build required?
  │
  ├── NO → CodeQL database
  │
  └── YES
       │
       ▼
  Build Sandbox
       │
       ▼
  CodeQL database
```

Sandbox requirements:

```text
CPU limit
RAM limit
timeout
restricted network
no credentials
isolated filesystem
temporary writable workspace
```

Default:

```yaml
build:
  sandbox: auto
```

If sandboxing isn't available:

```text
FAIL SAFE
```

Do not silently execute an untrusted build on the host.

An explicit:

```bash
--allow-unsafe-build
```

may be provided for trusted internal repositories.

---

# 17. Why not sandbox Python?

For a source-only Python CodeQL scan:

```bash
codeql database create ...
```

there is no need to execute the application's build.

Therefore:

```text
Python source analysis
→ no sandbox
```

If the project requires execution/build steps:

```text
build required
→ sandbox
```

This keeps the architecture simpler.

# 20. Fingerprinting

Generate:

```text
SHA256(
    normalized_file_path +
    rule_id +
    line +
    relevant_code_context
)
```

This is for correlation.

It is **not AI deduplication**.

# 21. Candidate grouping

Before calling the AI, reduce unnecessary API calls.

Group likely related findings using deterministic signals:

```text
same file
+
nearby line
+
same/similar CWE
+
same sink
+
similar fingerprint
```

Example:

```text
1,000 findings
       ↓
candidate grouping
       ↓
250 groups
       ↓
AI analysis
```

# 23. AI responsibilities

### Validation

```text
CONFIRMED
LIKELY
INSUFFICIENT_EVIDENCE
FALSE_POSITIVE
```

### Deduplication

Identify:

```text
same vulnerability
different scanner
different rule
same underlying source/sink
```

### Canonicalization

Example:

```text
"User input reaches SQL query"
       ↓
"SQL Injection"
```

### Better wording

Produce a professional description based only on evidence.

### Enrichment

Where justified:

```text
CWE
OWASP category
attack surface
exploitability
impact
remediation
```

# 24. AI must not hallucinate

Prompt requirements:

```text
Never invent code behavior.
Never claim exploitation without evidence.
Never invent a vulnerable data flow.
Never invent a file or function.
Never change scanner evidence.
If evidence is insufficient, say so.
```

This is critical.

# 26. Deduplication result

Suppose:

```text
OpenGrep #101
CodeQL #182
OpenGrep #209
```

all represent the same vulnerability.

AI returns:

```json
{
  "canonical_finding_id": "F-001",
  "duplicates": [
    "101",
    "182",
    "209"
  ]
}
```

Final report contains one canonical finding.

Raw evidence still contains all three.

# 27. Severity model

Preserve:

```text
scanner_severity
```

and separately produce:

```text
ai_severity
```

Example:

```json
{
  "scanner_severity": "WARNING",
  "ai_severity": "HIGH",
  "ai_confidence": 0.96
}
```

Never overwrite the scanner's original severity.

# 28. AI failure behavior

# 35. Security model

iSAST must:

* never use `shell=True` with repository-controlled input
* use subprocess argument arrays
* validate all paths
* enforce process timeouts
* enforce resource limits
* sandbox project builds
* avoid host credentials
* avoid passing secrets into build environments
* verify scanner downloads
* pin scanner versions
* restrict network during builds
* sanitize report content
* handle malicious repositories safely

---

# 36. CI/CD behavior

Example:

```bash
python isast.py \
    --source=. \
    --report=final.csv \
    --non-interactive
```

No interactive prompts.

No:

```text
sudo password
Press Y
Enter API key
```

AI credentials come from:

```text
.env
environment variables
CI secret store
```

Never from command-line arguments.

---

# 37. Exit codes

```text
0 = complete
1 = scanner/runtime failure
2 = invalid CLI arguments
3 = dependency installation failure
4 = invalid source
5 = partial scan
```

Finding severity should **not automatically determine the process exit code**.

That decision belongs to the CI/CD or ThreatVault policy layer.

---

# 38. `requirements.txt`

Keep iSAST dependencies small:

```text
python-dotenv
requests
PyYAML
```

Potentially:

```text
pydantic
```

for strict internal models.

Avoid making the scanner depend on large AI SDKs if the requirement is simply OpenAI-compatible HTTP. A small HTTP client keeps provider compatibility much easier.

# 40. Final product boundary

The most important architectural decision is:

```text
                    iSAST
                      │
        ┌─────────────┴─────────────┐
        │                           │
     Scanner                    AI Analyst
        │                           │
   OpenGrep                       Validate
   CodeQL                         Dedup
        │                         Normalize
        │                          Rewrite
        ▼                           Risk
  Raw evidence                      │
        │                           │
        └─────────────┬─────────────┘
                      ▼
                 Final Report
                      │
                      ▼
                 ThreatVault
```

**iSAST is deterministic scanning + orchestration. AI is the analysis layer.**

That separation is particularly important for your ThreatVault integration: you can always prove **what OpenGrep/CodeQL originally reported**, while separately showing **what the AI decided about that evidence**.

### Final user experience

```bash
python isast.py --source=/workspace/project --report=final.csv
```

Everything else—dependency installation, language detection, build detection, CodeQL database creation, OpenGrep execution, sandboxing, SARIF parsing, finding grouping, AI validation, deduplication, wording and CSV generation—is automatic.
